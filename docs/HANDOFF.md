## The Hugging Face Space

Free HF accounts cannot create Docker or CPU Spaces any more (402 Payment Required), so the Space uses the Gradio SDK on ZeroGPU hardware. ZeroGPU wants one `@spaces.GPU` function; ours is a no-op and never runs. The FastAPI app is served unchanged by uvicorn. Two workarounds live in `space/space_app.py`, both marked `ponytail:`:

1. The Space image pins `gradio[mcp]`, which needs `mcp<2`; Hindsight needs `mcp` 2. The app upgrades `mcp` at boot and drops the cached 1.x modules.
2. ZeroGPU reports decorated functions from inside `gr.Blocks.launch`, which we never call, so the app reports directly via `spaces.zero.client.startup_report()`.

If a future `spaces` or `gradio` release breaks either, read `hf spaces logs Auenchanters/hindsight` first. With HF PRO, a Docker Space using the repo `Dockerfile` removes both workarounds.

**Redeploy** after changing product code (from the repo root, after `hf auth login` as Auenchanters or a collaborator on the Space):

```bash
bash space/deploy.sh
```

**Add the keys to the Space** once we have the Nebius key. Secrets are not visible to visitors. This reads them from your local `.env`, so they never go through shell history; make sure that `.env` holds the Token Factory key, not the build.nvidia.com development setup below:

```bash
hf spaces secrets add Auenchanters/hindsight --secrets-file .env
```

Anyone who opens the public demo then spends our credits. The app caps it (`COPILOT_MAX_CONCURRENT`, default 2; `COPILOT_MAX_RUNS_PER_DAY`, default 200). Lower the daily cap with `hf spaces variables add Auenchanters/hindsight -e COPILOT_MAX_RUNS_PER_DAY=50` if spend is tight. `COPILOT_MCP_ALLOWED_HOSTS` is already set to the Space hostname.

## What is left, in order

### 1. Get a key (blocking everything below)

- **Nebius Token Factory key:** still needed for the submission. If there is none by **20 October**, chase the organizers that day.
- **Don't wait for it to start tuning.** NVIDIA's free API (build.nvidia.com) serves Nemotron through the same OpenAI-style API, and `copilot/config.py` already reads the base URL and model IDs from the environment. Put this in `.env` for development only (the submission must call Token Factory):

  ```
  NEBIUS_API_KEY=<the build.nvidia.com key>
  NEBIUS_BASE_URL=https://integrate.api.nvidia.com/v1
  COPILOT_MODEL_TRIAGE=<Nano ID as listed on build.nvidia.com>
  COPILOT_MODEL_REASON=<Ultra or Super ID as listed>
  COPILOT_MODEL_WRITER=<Super ID as listed>
  ```

  Costs printed by the CLI will read $0 there, since the price table is keyed by Token Factory IDs.

### 2. Real runs (with any key)

Put keys in `.env` in the repo root. Never commit it and never paste it in chat. Then:

1. **Check the model names.** `python -m copilot models`. Fix any reported missing in `.env` or `copilot/config.py`.
2. **Run one investigation and read it.** `python -m copilot investigate --seed 42 --difficulty medium --out postmortem.md`. Look for unparseable replies, wasted lookups and a wrong or uncited diagnosis. Read the cost per model it prints, and **estimate the benchmark's cost before running it**.
3. **Run the demo incident too**: `python scripts/make_demo_incident.py`, then `python -m copilot investigate --file demo/checkout-incident/incident.json --out postmortem.md`. It is graded, because `incident.json` carries the answer.
4. **Tune the prompts** only for what you saw fail. They are `TRIAGE_SYSTEM` and `DIAGNOSIS_SYSTEM` in `copilot/investigator.py`, and `WRITER_SYSTEM` in `copilot/report.py`.
5. **Benchmark in small steps.** `--seeds 0-4` first, then `python -m copilot bench --seeds 0-49 --difficulty medium --label routed --out benchmarks/routed-medium.json`, then easy and hard. Results appear on the home page leaderboard.
6. **Routing ablation.** Rerun with `--triage` and `--reason` set to the same model (Ultra-only, Super-only), each with its own `--label`. Accuracy against dollars on the same seeds is the core of "how we use Nemotron".
7. **Record real runs.** `python -m copilot investigate --seed 42 --difficulty medium --record copilot/recordings/seed-42-medium.json`, plus one hard seed and the demo incident. Recordings replay on the hosted demo without spending anything. Then `bash space/deploy.sh`.
8. **Put only measured numbers in the README.** A test checks this.

## Run it locally

Python 3.11 or later (3.13 works).

```bash
git clone git@github.com:jacklachan/Nebius-x-NVIDIA.git
cd Nebius-x-NVIDIA
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest tests/ -q
.venv/Scripts/python -m uvicorn app:app --port 7860
```

On macOS or Linux use `.venv/bin/python`. On Windows, if `python` is 3.10, use `py -3.13 -m venv .venv`.

## Things that will trip you up

- **Do not kill all Python processes** to stop a server. It takes down every other Python program on the machine. Stop the one process by its ID.
- **Do not commit dev-server output as a recording.** `scripts/dev_ui_server.py` uses a stand-in that reads the answer. Only real runs go in `copilot/recordings/`.
- **The MCP path is `/api/copilot/mcp`**, not `/mcp`. A hosted deployment also needs `COPILOT_MCP_ALLOWED_HOSTS` set to its hostname.
- **MCP SDK is version 2.** `FastMCP` is now `MCPServer`, and errors meant for the caller must be raised as `ToolError`. This is also why the Space needs its boot-time `mcp` upgrade.
- **The Space is deployed separately from GitHub.** Pushing to `main` does not update it; run `bash space/deploy.sh`.
- **Hand-written sample incidents score low on failure modes** because their chains use free-text labels. Root cause and failure path are the scores to read there.
- **Commit in small pieces** with tests passing, and push to `main`. CI runs the tests on Python 3.11 and builds the Docker image.
- **No numbers in the README that we have not measured.** The baselines and oracle rows are reproducible from the code, and a test checks that.
- **ruff reports about 580 style findings** with its newer default rules, mostly in legacy code. None are bugs; CI's lint step is non-blocking on purpose.
